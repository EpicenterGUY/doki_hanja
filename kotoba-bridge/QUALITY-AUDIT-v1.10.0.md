## 교정 대상과 처리 방식
- 학습자가 보는 어휘 표제어에서 **띄어쓰기 보정 후보 78건** 적용. 같은 78개의 한국어 예문에도 대응하는 띄어쓰기 변경을 반영.
- 예: `정체성형성 → 정체성 형성`, `공급망교란 → 공급망 교란`, `통계적유의성 → 통계적 유의성`, `외교적해법 → 외교적 해법`, `개인정보보호 → 개인정보 보호`.
- 기존 `ko`와 `id` 필드를 보존한 채 표시 전용 `displayKo`를 사용해 구형 학습 자료와의 호환성을 유지. 전체 매핑은 `vocabulary-v20-orthography.js`에 명시되어 있다.
- 단어장, 일본어↔한국어 플래시카드, 객관식 선택지, 주관식 입력·정답 표시, 검색에서 교정 표기가 동일하게 사용된다. 주관식은 한글 NFC 정규화와 연속 공백 정리는 허용하되, 틀린 합쳐쓰기 자체를 자동 정답 처리하지 않는다.
- 일본어 통계 학습 문장에서 `유의미하다`의 의미를 일반적인 '有意義'와 통계적인 '統計的に有意' 중 후자로 더 정확히 구별하도록 예문을 수정했다.

### 중복 카드 및 저장 기록 보존
- 기존 `도덕적해이`(`ha60102`)와 `도덕적 해이`(`r11a7-0116`)는 실제로 동일 어휘. 화면에 한 카드만 나타나도록 병합해 5,463→**5,462** 고유 카드로 조정.
- 살아남은 표제어는 L6으로 배정; 해당 의미에 대해 별도 L7 복제 카드를 남기지 않는다.
- `KB_VOCAB_ID_ALIASES`로 예전 ID를 연결. 사용자의 저장 카드 횟수, 단계 및 즐겨찾기를 합친 카드로 이전하는 절차를 `vocab-ui.js`의 로드·JSON 가져오기에 추가.
- 실제 학습 저장 모의 데이터에서 복습 횟수 4+1→5, 정답 횟수 3+1→4, 즐겨찾기 유지 및 이전 ID 제거까지 확인.

## 자동 회귀 검사
- `audit-data.cjs`: 표시 표제어 중복 여부, 과거 ID 별칭의 무결성, 보정 건수, 남은 기본형·품사 검토 후보를 보고.
- `test-vocab-quality.cjs`: 전체 어휘 실행, 한일 예문 보존, 표기 변경 및 검색, 주관식 맞춤법 정답 판정, 저장 기록 이관에 대한 무의존 Node 통합 테스트.
- `.github/workflows/kotoba-data-audit.yml`: 해당 테스트를 기존 문법·어휘 구조 검사에 추가.

실행:
```bash
node kotoba-bridge/audit-data.cjs --json
node kotoba-bridge/test-vocab-quality.cjs
```

## 검수 한계와 다음 할 일
1. **78건은 학습용 띄어쓰기 편집 후보**이며 공인 사전과 1:1 완전 대조한 확정 표준어 목록은 아니다. 기술 용어의 전문 분야 관용 표기와 합성어 사전 등재 여부를 단계적으로 검증해야 한다.
2. 기본형·용법 판정을 보류한 예: `기인되다`, `대두하다`, `종합적`, `주관적`. 사전적 명사·형용사 구분 및 부자연스러운 활용을 추가 검토한다.
3. 한국어 예문과 일본어 의미 대응에 대한 원어민 전수 감수는 완료되지 않았다. 수록률 100%는 비어 있지 않은 **두 언어의 예문 필드**를 뜻한다.
4. 공개 배포 사이트의 기기별 실제 UI, GitHub Actions 실행 로그의 성공 여부는 이 소스 검수만으로 확정하지 않는다.

단어별 TOPIK 공식 배정으로 단정하지 않으며 L7·L8은 본 프로젝트의 독자적인 고급 확장 단계다.
